# Build 0031 — Session Arbitrator transport foundation

`session_arbitrator` is now a separate executable on POSIX systems, listening on a local Unix-domain stream socket (default `/tmp/rdpd-arbitrator.sock`, or a single command-line path argument). The socket is created with filesystem permissions 0600; the server refuses to overwrite an existing path. Use a private directory for deployments with untrusted local users. This is an experimental single-client-at-a-time service; do not expose it on TCP.

`ipc_transport.c` sends and receives complete version-1 IPC frames using short-read/write loops, and delegates all validation to `ipc.c`. The arbitrator requires a HELLO negotiation before accepting SESSION_OPEN. It acknowledges the session open, responds to HEARTBEAT, and accepts SESSION_CLOSE. Session IDs and request correlation IDs are echoed in responses. Application, input, and window messages currently receive STATUS=1 (not implemented); **no desktop dispatch occurs yet**. The running RDP server remains in-process and is not connected to the arbitrator. This preserves the existing server while we build the integration.

Build on Linux with `make`, then run `./session_arbitrator /tmp/my-arbitrator.sock`. `python tests/test_arbitrator.py` launches a temporary arbitrator, negotiates HELLO, opens a session, tests the unimplemented app-launch response, checks heartbeat and closes. On Windows the executable is an explicit unsupported stub and the Unix-socket integration test skips; Windows local transport will require a separate implementation.

Limitations: no client credential verification beyond socket permissions, no concurrent clients, no desktop process, no framebuffer sharing, no application launch, no restart supervision, and no protocol timeouts. A client that holds a connection open can block other clients. The next sprint should implement nonblocking/concurrent client handling, peer credentials, and a dispatch bridge to the existing session code before enabling the RDP server to use IPC.
